[1] Trace Indexer: parses and indexes the student's learning history

solutions

Backend

I will explain you the flow

1.
Professor creates one exercise, LLM will read exercise and see labels table. If he finds good label he suggests it otherwise he suggests a new one.
Professor clicks other submit button that should add those labels.

2.
Professor can grades exam exercise.

3.

Study plan Button triggers the whole process.
It will compute the score for every label in the table Labels.

Label Strenght is computed by retrieving exercise logs of the student
It must be computed following some rules that the LLM needs to know such as.
Exam questions are more important, and recent scores must give a more impactful score.
Topics without any exercise done should have 0 score.

The LLM should output a Json file with a list such as:
{
{
    label: "Adition"
    score: 30,
    trend: declining,
    llm_reasoning: ...
}
{
    label: "Subtraction"
    score: 70,
    trend: improving,
    llm_reasoning: ...
}
}

The LLM should output a Json file that lists for each label in the label-list:
A score - an indicator of severity of how badly the student is doing in this topic, (0 - very bad, 100 - excellent)
Trend - indicates trend, should consider recent timestamps
reasoning - LLMs notes about why the scores were chosen, like "student failed in exercise 7". These are mostly LLMs notes to its future self.

4.
After that in another call the LLM uses that information to create a second list, called the study plan.
The study plan is a list of study blocks, each with a list of exercises suggested, LLM decides them based on the score and reasoning. Try not to overload with topics he has done a lot in recent times.

5.
After we receive These two, The Nudge engine will create an actionable nudge to the student, asking them to do an exercise from the studyplan from the topic with the worst score.

6.
The student can click on it and will be directed to the study plan page. /study_plan
There he can do the exercise, submit a solution and if correct the system compares it to the solution if its the same grade it Correct, if not grade it Incorrect.
If submitted correctly load next exercise.

​PRAGMA foreign_keys = ON;


-- =========================
-- STUDENT
-- =========================
CREATE TABLE student (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE,
    created TEXT NOT NULL
);


-- =========================
-- COURSE
-- =========================
CREATE TABLE course (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    professor TEXT
);


-- student can enroll in many courses
CREATE TABLE student_course (
    student_id INTEGER NOT NULL,
    course_id INTEGER NOT NULL,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES student(id),
    FOREIGN KEY (course_id) REFERENCES course(id)
);


-- =========================
-- LABELS
-- =========================
CREATE TABLE labels (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    course_id INTEGER NOT NULL,
    FOREIGN KEY (course_id) REFERENCES course(id)
);


-- =========================
-- EXAM
-- =========================
CREATE TABLE exam (
    id INTEGER PRIMARY KEY,
    course_id INTEGER NOT NULL,
    created TEXT NOT NULL,
    FOREIGN KEY (course_id) REFERENCES course(id)
);


-- =========================
-- EXERCISE
-- =========================
CREATE TABLE exercise (
    id INTEGER PRIMARY KEY,
    course_id INTEGER NOT NULL,
    text TEXT NOT NULL,
    solution TEXT,
    difficulty INTEGER,
    created TEXT NOT NULL,
    type TEXT CHECK(type IN ('exam', 'quiz')),
    FOREIGN KEY (course_id) REFERENCES course(id)
);


-- exam contains many exercises
CREATE TABLE exam_exercise (
    exam_id INTEGER NOT NULL,
    exercise_id INTEGER NOT NULL,
    PRIMARY KEY (exam_id, exercise_id),
    FOREIGN KEY (exam_id) REFERENCES exam(id),
    FOREIGN KEY (exercise_id) REFERENCES exercise(id)
);


-- exercise can have many labels
CREATE TABLE exercise_label (
    exercise_id INTEGER NOT NULL,
    label_id INTEGER NOT NULL,
    PRIMARY KEY (exercise_id, label_id),
    FOREIGN KEY (exercise_id) REFERENCES exercise(id),
    FOREIGN KEY (label_id) REFERENCES labels(id)
);


-- =========================
-- EXERCISE LOG
-- =========================
CREATE TABLE exercise_log (
    id INTEGER PRIMARY KEY,
    exercise_id INTEGER NOT NULL,
    student_id INTEGER NOT NULL,
    execution_type TEXT CHECK(execution_type IN ('exam', 'individual')),
    created TEXT NOT NULL,
    FOREIGN KEY (exercise_id) REFERENCES exercise(id),
    FOREIGN KEY (student_id) REFERENCES student(id)
);


-- =========================
-- LABEL STRENGTH
-- =========================
CREATE TABLE label_strength (
    id INTEGER PRIMARY KEY,
    student_id INTEGER NOT NULL,
    label_id INTEGER NOT NULL,
    score REAL,
    trend REAL,
    llm_reasoning TEXT,
    updated TEXT NOT NULL,
    FOREIGN KEY (student_id) REFERENCES student(id),
    FOREIGN KEY (label_id) REFERENCES labels(id)
);


-- =========================
-- STUDY PLAN
-- =========================
CREATE TABLE study_plan (
    id INTEGER PRIMARY KEY,
    course_id INTEGER NOT NULL,
    student_id INTEGER NOT NULL,
    created TEXT NOT NULL,
    FOREIGN KEY (course_id) REFERENCES course(id),
    FOREIGN KEY (student_id) REFERENCES student(id)
);


-- =========================
-- STUDY BLOCK
-- =========================
CREATE TABLE study_block (
    id INTEGER PRIMARY KEY,
    study_plan_id INTEGER NOT NULL,
    block_order INTEGER NOT NULL,
    topic_id INTEGER NOT NULL,
    FOREIGN KEY (study_plan_id) REFERENCES study_plan(id),
    FOREIGN KEY (topic_id) REFERENCES labels(id)
);


-- study block contains many exercises
CREATE TABLE study_block_exercise (
    study_block_id INTEGER NOT NULL,
    exercise_id INTEGER NOT NULL,
    PRIMARY KEY (study_block_id, exercise_id),
    FOREIGN KEY (study_block_id) REFERENCES study_block(id),
    FOREIGN KEY (exercise_id) REFERENCES exercise(id)
);
